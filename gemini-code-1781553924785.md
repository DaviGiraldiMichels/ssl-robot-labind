# Contexto do Projeto: Robô Móvel com STM32F401RE (Small Size League - SSL)

Você está auxiliando um desenvolvedor de sistemas embarcados a programar um robô móvel utilizando o Gemini no VS Code. Use as especificações abaixo para garantir que todo código gerado seja compatível e seguro para o hardware real.

## 1. Especificações do Hardware Principal
- **Microcontrolador:** STM32F401RE (Placa Nucleo-64)
- **Ambiente de Desenvolvimento:** STM32CubeIDE / VS Code com extensão STM32
- **Framework/Biblioteca:** STM32Cube HAL (Hardware Abstraction Layer) em Linguagem C
- **Frequência de Clock do Sistema:** 84 MHz (Configuração padrão da Nucleo-F401RE)
- **Motores e Tração:** 4 Motores Brushless 2200kv com Rodas Omnidirecionais (Cinemática SSL).
- **Drivers de Motor:** 4 ESCs LittleBee-Spring 30A (Modificados para modo bidirecional).

## 2. Arquitetura de Alimentação (Energia)
- **Fonte de Energia:** Bateria LiPo 2S (Tensão Nominal: 7.4V | Tensão Carga Máxima: 8.4V | Capacidade: 2200mAh | Taxa Descarga: 45C)
- **Alimentação da Placa:** - *Fase de Testes:* Bateria ligada diretamente ao pino `VIN` e `GND` da Nucleo (Jumper JP5 configurado na posição VIN).
  - *Fase Final:* Bateria ligada a um módulo Step-Down robusto ajustado para 5.0V fixos, alimentando o pino `5V` da placa.

## 3. Isolamento de Sinal e Periféricos
- **Módulo Optoacoplador PC817 (2 Canais):** Utilizado obrigatoriamente para isolar os pinos de sinal lógico do STM32 dos ruídos elétricos do Driver de Motor.
- **Regra de Código:** Os pinos do STM32 configurados para controlar os motores via PWM devem acionar os LEDs internos do PC817. (Pinos Atuais: `PA0`, `PA1`, `PB10`, `PB0`).
- **SPI e Comunicação:** Pinos D9 a D13 estão reservados para a comunicação com o módulo de rádio nRF24L01.

## 4. Arquitetura de Comunicação e Controle
- **Fluxo de Comando:** Computador (com controle/joystick) -> Arduino Uno -> [Via nRF24L01] -> STM32 -> [Via PWM] -> ESCs -> Motores Brushless.
- O STM32 atua primariamente como um nó receptor e calculador de cinemática: ele recebe do Arduino os vetores de velocidade desejados e aciona os motores imediatamente.

## 5. Diretrizes de Programação e Geração de Código
- **Configuração de Pinos:** Sempre utilize os periféricos nativos do STM32. A direção e velocidade serão controladas apenas pelo pulso PWM do ESC (1000us a 2000us), sem necessidade de pinos digitais dedicados para direção.
- **Abstração HAL:** Todo código de controle de hardware deve usar funções como `HAL_GPIO_WritePin`, `HAL_TIM_PWM_Start`, e estruturas de inicialização padrão da HAL.
- **Comentários:** O código deve conter comentários claros explicando quais pinos (evitando os pinos D9 a D13 do SPI) e quais Timers (ex: `TIM2` e `TIM3`) estão sendo sugeridos.
- **Segurança Elétrica:** Nunca sugira configurações que exijam mais de 25mA por pino do STM32.

## 6. Objetivos Concluídos
- **Comunicação e Controle:**
  - **Sincronização Serial End-to-End:** Implementado cabeçalho de sincronia (`0xAA`, `0x55`) entre o script Python e o Arduino, evitando erros de enquadramento.
  - **Debug Bidirecional:** O Arduino avalia a chegada dos comandos e o status de ACK do rádio, retornando as informações via porta Serial para o script Python.
  - **Geração de PWM (50Hz):** `TIM2` e `TIM3` configurados para gerar o sinal de controle para os 4 motores.
- **Failsafe de Comunicação:** Lógica de segurança de hardware implementada no STM32. Ausência de pacotes válidos por mais de 200ms aciona uma parada de emergência automática (motores em 1500us).
- **Cinemática e Calibração:**
  - **Correção da Matriz Cinemática:** Ajustada a matriz no `ssl_kinematics.c` para que os vetores de velocidade (`vx`, `vy`) correspondam ao movimento físico desejado (frente, strafe).
  - **Mapeamento e Direção dos Motores:** Identificado o mapeamento físico de cada motor e corrigida a direção de rotação individualmente no firmware.
  - **Calibração de Deadzone:** Identificado o ponto neutro real dos motores (~1490us) e a zona morta (1465-1515us). Implementada compensação no firmware para garantir partida síncrona e suave dos motores.

## 7. Próximos Passos
- **Calibração dos ESCs:** Configurar o firmware dos LittleBee via BLHeliSuite para habilitar o modo **Bidirectional 3D**, permitindo operação com neutro em 1500us, ré em 1000us e avanço máximo em 2000us.
- **Isolamento Físico:** Realizar a soldagem dos módulos optoacopladores PC817 como ponte isolada entre o STM32 (`PA0`, `PA1`, `PB10` e `PB0`) e os cabos de sinal de cada ESC.
